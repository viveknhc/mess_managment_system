How to run Mess Manager

Clone the repo and get the app running on your own computer in about 10 minutes. You don't need a database server, Redis, Docker or any config files; everything runs locally.

3 · Step by step

  1. Get the code any terminal

    git clone https://github.com/viveknhc/mess_managment_system.git
cd mess_managment_system

    You now have a mess_managment_system folder with backend/, frontend/ and docs/ inside.

  2. Create a Python virtual environment Terminal 1

    This keeps the project's packages separate from the rest of your computer.

    cd backend
python3 -m venv .venv
source .venv/bin/activate
    cd backend
py -m venv .venv
.venv\Scripts\Activate.ps1

    Your prompt now starts with (.venv). Keep using this terminal for the backend.

  3. Install backend packages Terminal 1

    pip install -r requirements.txt

    Ends with "Successfully installed Django… djangorestframework… pytest…". Takes about a minute.

  4. Create the database Terminal 1

    python manage.py migrate

    A list of "Applying … OK" lines. This creates backend/db.sqlite3, a local file database. No database server is needed.

  5. Load demo data Terminal 1

    python manage.py seed_data

    Creates the demo business "Annapurna Mess": 20 customers, 5 plans, subscriptions in every state, payments and deliveries. At the end it prints a table of login usernames and passwords. Keep it handy.

  6. Create a platform admin Terminal 1 · optional

    Only needed to test the SaaS / platform admin area (/platform). Pick your own password in place of choose-a-password:

    python manage.py shell -c "from apps.accounts.models import User; User.objects.create_user(username='superadmin', password='choose-a-password', role='SUPER_ADMIN', is_staff=True, is_superuser=True)"
    python manage.py shell -c "from apps.accounts.models import User; User.objects.create_user(username='superadmin', password='choose-a-password', role='SUPER_ADMIN', is_staff=True, is_superuser=True)"
    Don't use python manage.py createsuperuser for this. It creates a user with role CUSTOMER, which lands in the customer portal instead of the platform admin area.

  7. Start the backend Terminal 1

    python manage.py runserver

    "Starting development server at http://127.0.0.1:8000/". Leave this terminal running.

  8. Install and start the frontend Terminal 2 (new window)

    Open a second terminal in the mess_managment_system folder:

    cd frontend
npm install
npm run dev

    "VITE … ready" and "Local: http://localhost:5173/". You may also see a yellow warning about __dirname; it's harmless.

  9. Open the app browser

    Go to http://localhost:5173. You'll see the landing page. Click Login, then continue below.

git pull

This deletes everything in your local database, including any business you signed up and the platform admin, then reloads the demo data. Re-run step 6 afterwards if you need the platform admin.

6 · Troubleshooting

"python3: command not found" or "python: command not found"

macOS / Linux use python3 until the venv is active; after that, python works. On Windows use py to create the venv, or reinstall Python with "Add python.exe to PATH" ticked.

Windows: "running scripts is disabled on this system" when activating

PowerShell blocks the activate script by default. Run this once, then activate again:

Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
"No module named django" (or any other module)

The virtual environment isn't active in this terminal. Activate it (step 2) and try again. Your prompt should start with (.venv).

seed_data says: Business "Annapurna Mess" already exists

The demo data is already loaded, so you can just log in. To reload it from scratch, use python manage.py seed_data --reset (this deletes all local data).

Login says "Invalid username or password"

Check that seed_data ran successfully and that you're using its printed usernames. Five wrong attempts within a minute temporarily blocks logins; wait a minute.

The page loads but nothing works / network errors

The backend isn't running. Check Terminal 1 shows "Starting development server at http://127.0.0.1:8000/". The frontend forwards all /api requests to port 8000.

Open the app at http://localhost:5173, not 127.0.0.1:5173. The frontend dev server only listens on localhost.

"That port is already in use" (8000 or 5173)

Another copy is probably already running. Close it, or stop whatever uses the port. The frontend expects the backend on 8000, so if you must use another backend port (e.g. 8001), start the frontend like this:

python manage.py runserver 8001
# Terminal 2:
VITE_API_BASE_URL=http://localhost:8001/api/v1 npm run dev
python manage.py runserver 8001
# Terminal 2:
$env:VITE_API_BASE_URL="http://localhost:8001/api/v1"; npm run dev
npm errors about the Node version, or "crypto.hash is not a function"

Your Node.js is too old for Vite 8. Install Node 22 LTS (or at least 20.19) from nodejs.org, delete frontend/node_modules, and run npm install again.

Settings and environment variables

Nothing is required for local use; sensible defaults are built in. To override something, copy .env.example (repo root) to backend/.env and edit it. Useful keys:

  • DATABASE_URL: use PostgreSQL instead of SQLite, e.g. postgres://user:pass@localhost:5432/mess_db.
  • SECRET_KEY, DEBUG, ALLOWED_HOSTS: needed for any real deployment.
  • CELERY_BROKER_URL: Redis address for background jobs (see below).
  • RAZORPAY_KEY_ID / RAZORPAY_KEY_SECRET: online SaaS billing. Leave empty locally; plans without a Razorpay Plan ID activate instantly.
Background jobs (Celery + Redis)

The app works fully without these. Celery only runs scheduled jobs such as the daily trial-expiry check. To try it, install and start Redis, then in another terminal with the venv active:

celery -A config worker --beat -l info

Not part of the regular test flow.

Docker

The repo has a docker-compose.yml (PostgreSQL, Redis, backend, frontend), but it isn't the tested path yet. It needs a .env.docker file that isn't in the repo, and the frontend container's API forwarding may need adjusting. Use the steps above unless you're working on the Docker setup itself.

Where things are in the code
  • backend/apps/: one Django app per area (customers, plans, subscriptions, payments, deliveries, platform, …)
  • backend/common/: shared base classes (multi-tenant filtering, permissions, errors)
  • frontend/src/features/: one folder per screen area; frontend/src/components/ui/ holds shared UI like the data table
  • docs/: specs, task tracker (tasks.md), progress page and this guide
