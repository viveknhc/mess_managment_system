1Before you start

  • All code is pushed to main on GitHub (viveknhc/mess_managment_system). Every host deploys from there.
  • CI is green on GitHub (Actions tab). Don't deploy a red build.
  • Decide these and write them down in a password manager:
    • a super admin password (the platform login you use to create businesses and record payments)
    • a backup passphrase (long and random; without it backups can't be opened)

2Database: Neon

  1. Go to neon.tech, sign up, then Create project.
    • Name: messdeck
    • Postgres version: the default (17 is fine)
    • Region: Asia Pacific (Singapore), close to your clients and to Render
  2. On the project dashboard click Connect, turn off Connection pooling (use the direct connection) and copy the connection string: 
    postgresql://neondb_owner:xxxx@ep-xxxx.ap-southeast-1.aws.neon.tech/neondb?sslmode=require
    This is your DATABASE_URL. Keep it private: anyone with it can read all client data.

3API: Render

  1. Go to render.com, sign up with GitHub and allow access to the repo.
  2. New + → Blueprint → pick the repo. Render reads render.yaml and shows a service called mess-manager-api.
  3. Fill in the values it asks for:
    KeyValue
    DATABASE_URLThe Neon connection string from step 2
    SUPERADMIN_PASSWORDYour super admin password
    CORS_ALLOWED_ORIGINShttps://example.com for now. You'll fix it in step 5.
    EMAIL_HOST etc.Leave empty. The alert emails are sent by the nightly job (step 7), not by Render.
  4. Leave SEED_DEMO at 0. Set it to 1 only for a separate demo instance; demo logins are public.
  5. Click Apply. The first build takes 3–5 minutes. It installs packages, creates the tables and creates the superadmin user.
  6. When it shows Live, copy the URL at the top, e.g. https://mess-manager-api.onrender.com. Open https://<render-url>/api/v1/pricing/ in a browser: you should see a JSON response, not an error page.

4Website: Vercel

  1. Go to vercel.com, sign up with GitHub, then Add New… → Project → import the repo.
  2. Settings:
    • Root Directory: frontend (click Edit and choose it). This matters: it's what makes page refreshes work.
    • Framework preset: Vite (auto-detected)
    • Environment Variables:
      KeyValue
      VITE_API_BASE_URLhttps://<render-url>/api/v1
  3. Click Deploy. After about a minute you get a URL like https://messdeck.vercel.app.
Support contact is built in. The landing page, Billing page and Help & Support use WhatsApp +91 85477 68153 and viveknhc@gmail.com (set in frontend/src/config/support.ts). To change them without editing code, add VITE_SUPPORT_WHATSAPP (digits only, with 91) and VITE_SUPPORT_EMAIL here. Vite reads VITE_* variables at build time, so redeploy after changing any of them (Deployments → ⋯ → Redeploy).

5Connect website and API

In Render → mess-manager-api → Environment, set CORS_ALLOWED_ORIGINS to your Vercel URL exactly: https://messdeck.vercel.app (https, no trailing slash). Save changes; Render redeploys by itself.

6Nightly jobs and backups (GitHub Actions)

Render's free plan can't run background workers, so two GitHub workflows do it:

WorkflowWhenWhat it does
Daily jobs00:10 ISTSuspends overdue businesses, expires finished subscriptions, starts and ends pauses, prepares tomorrow's deliveries, sends expiry alerts
Daily DB backup02:00 ISTEncrypted copy of the whole database, kept for 30 days
  1. On GitHub: repo → Settings → Secrets and variables → Actions → New repository secret. Add:
    SecretValue
    PROD_DATABASE_URLThe Neon connection string (same as Render's DATABASE_URL)
    PROD_SECRET_KEYAny long random string (e.g. from a password generator)
    BACKUP_PASSPHRASEYour backup passphrase from step 1
  2. Actions tab → Daily jobs → Run workflow. It should finish green, with one OK line per job in the log.
  3. Actions → Daily DB backup → Run workflow. When it's green, the run page shows an artifact named messdeck_YYYYMMDD_HHMM.
Until these secrets exist, nothing runs. Both workflows skip quietly, so unpaid businesses are never suspended, subscriptions never expire and no backups are taken. Also, GitHub pauses scheduled workflows after 60 days with no commits to the repo; if that happens, re-enable them from the Actions tab.
Test one restore now, not on the day you need it. Steps are in docs/db_backup_restore.md: download the artifact, decrypt with your passphrase, and pg_restore into a spare Neon branch. Then delete the branch.

7Alert emails

Every night, owners get a summary of subscriptions ending in the next 3 days, and customers with an email address get a reminder. Without an email provider, these only appear in the job log.

Simplest option, a Gmail account: turn on 2-step verification, then create an App password (Google Account → Security → App passwords). Gmail limits how many emails you can send per day, so move to a provider such as Brevo or Zoho Mail as you add clients.

Add these as GitHub secrets (same place as step 6):

SecretGmail example
EMAIL_HOSTsmtp.gmail.com
EMAIL_HOST_USERyourname@gmail.com
EMAIL_HOST_PASSWORDThe 16-character app password
DEFAULT_FROM_EMAILMessDeck <yourname@gmail.com>

Port 587 with TLS is the default, so no other settings are needed for Gmail. Run Daily jobs again by hand; if any subscription is expiring, the owner's email should arrive.

8Online payments: Razorpay

Two kinds of online payment, kept separate:

  • Mess owners pay you the MessDeck fee with a Pay now button on their Billing page. The money goes to your Razorpay account.
  • Customers pay their mess for a meal plan from the customer portal. The money goes to that owner's own Razorpay account. Each owner adds their keys in Settings → Online Payments, and you never handle their money.

Without keys, the buttons are hidden and everything works as before: payments are recorded by hand.

  1. Sign up at razorpay.com. You can start in Test Mode straight away; real payments need KYC (PAN, bank account, business details) and take a few days to approve.
  2. Razorpay Dashboard → Account & Settings → API Keys → Generate key. Copy the Key ID and Key Secret (the secret is shown once).
  3. Render → mess-manager-api → Environment, add:
    KeyValue
    RAZORPAY_KEY_IDrzp_test_… (later rzp_live_…)
    RAZORPAY_KEY_SECRETThe key secret
    RAZORPAY_WEBHOOK_SECRETAny long random string, the same one you use in the next step
  4. Razorpay Dashboard → Account & Settings → Webhooks → Add new webhook: URL https://<render-url>/api/v1/webhooks/razorpay/, the same secret, and event order.paid. This catches owners who pay and close the tab before the page confirms.
  5. Log in as an owner → Billing → Pay now. In Test Mode, pay with UPI ID success@razorpay or test card 4111 1111 1111 1111 (any future expiry, any CVV). The plan should turn Active.

For each mess owner who wants customer payments: they create their own Razorpay account, generate API keys, and paste them in Settings → Online Payments, then tick Customers can pay online. Customers then see a Pay button on My Subscription. A paid subscription turns Active and its deliveries are created, the same as a recorded cash payment.

Owners' key secrets are stored encrypted using the server's SECRET_KEY. If you ever change SECRET_KEY on Render, owners must paste their key secret again. To avoid that, set a separate FIELD_ENCRYPTION_KEY (any long random string) before owners add keys, and never change it.

9Check everything works

  1. Open your Vercel URL. The Contact Us button on the landing page should open WhatsApp chat with +91 85477 68153.
  2. Log in as superadmin with your password. You should land on the Platform dashboard.
  3. Open https://<render-url>/admin/ and log in as superadmin too. This is the raw database admin; use it only to fix problems.

10Onboard your first client

  1. Platform → Businesses → Add Business. Enter the mess's name and contact details, and an owner username and password for them.
  2. When they pay ₹3,000 (₹2,500 setup + ₹500 first month), click Record Payment on their row. The amount is filled in; choose UPI, Cash or Bank transfer and add the UPI reference.
    If no payment is recorded within 7 days of adding the business, the nightly job suspends it.
  3. Log in as the owner (or sit with them) and set up: Meals, Plans, Staff logins, then Customers → Import CSV with their existing list (up to 100 per file).
  4. Do the 30-minute walkthrough with docs/owner-guide.html and leave them a copy.
  5. Each month, record their ₹500 the same way. The Businesses list shows who is paid until when and what's due.

11Own domain (optional)

For example app.messdeck.in for the website and api.messdeck.in for the API.

  1. Vercel → project → Settings → Domains → add app.messdeck.in and create the DNS record it shows at your domain registrar.
  2. Render → service → Settings → Custom Domains → add api.messdeck.in and create its DNS record.
  3. Render → Environment:
    • ALLOWED_HOSTS = api.messdeck.in
    • CORS_ALLOWED_ORIGINS = https://app.messdeck.in (add the Vercel URL too, comma-separated, if you still use it)
  4. Vercel → VITE_API_BASE_URL = https://api.messdeck.in/api/v1, then redeploy.

Both hosts issue HTTPS certificates automatically once DNS is set up.

12Updating and day-to-day

  • Deploying changes: push to main. Render and Vercel redeploy automatically; database migrations run during the Render build.
  • Each morning: glance at the Actions tab. Both nightly workflows should be green. GitHub emails you when a workflow fails.
  • Changing the super admin password: change SUPERADMIN_PASSWORD on Render; it's applied on the next deploy.
Free-tier limits that clients will notice
  • The API sleeps after about 15 minutes without traffic, and the next visit takes 30–60 seconds to load. Before the first paying client, move the Render service to a paid instance (Render → service → Settings → Instance type) so it stays awake.
  • Logo uploads don't persist on Render's free disk; they disappear on every deploy. A file storage service (e.g. Cloudinary or S3) would be needed for logos.
  • Neon free has a storage cap and a short restore history; check usage in the Neon dashboard as clients grow.

13Troubleshooting

SymptomFix
Every login says "Invalid username or password"The API is asleep or the URL is wrong. Open https://<render-url>/api/v1/pricing/ and wait for it to load. Then check Vercel's VITE_API_BASE_URL ends in /api/v1 and redeploy.
Browser console shows a CORS errorCORS_ALLOWED_ORIGINS on Render must exactly match the website address (https, no trailing slash).
Refreshing a page like /app/customers gives 404Vercel's Root Directory must be frontend.
Render build fails at migrateDATABASE_URL is wrong or missing ?sslmode=require.
Render says the Python version isn't foundChange PYTHON_VERSION in Render → Environment to a 3.12.x version Render lists.
Daily jobs workflow says "skipping"The PROD_DATABASE_URL secret is missing or misspelled.
Daily jobs fails with a missing column or tableThe database is behind the code. Check the latest Render deploy succeeded (it runs the migrations), then re-run the workflow.
Backup fails with "server version mismatch"Neon was upgraded past PostgreSQL 17. In .github/workflows/db-backup.yml, change 17 to the new version in both places.
No alert emails arriveCheck the Daily jobs log. "console" output means EMAIL_HOST isn't set; an SMTP error usually means a wrong app password.
A client says they're locked outThey're probably suspended for non-payment. Record their payment (Platform → Businesses → Record Payment) and access comes back immediately.
